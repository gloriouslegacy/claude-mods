# v2.12.0 명세 — 주간 알림 문턱 분리 · 자동 이어하기 (qhud)

배경: v2.11.0 알림(`docs/spec/v2.11.0.md` F1)을 넓힌다. 사용자 결정(2026-11-16): 주간 문턱 2%, 한도 리셋 시각에 작업 자동 재개 설정 `autoResume`, 켜져 있으면 메인 알림 문구에 재개 예약을 함께 알림. 나머지는 메인 권장안(자동 결정): 새 키 추가(이름 변경 없음), 실제 소진 시에만 예약, 고정 문구.

## F1 qhud 0.20.0 — 주간 알림 문턱 분리
- userConfig 새 키 `alertLeftWeekly`(number, 기본 2, "Weekly alert threshold (% left)", 1~50 밖이면 2 로 본다). 적용 창: `seven_day` + 모델별 주간 창.
- 기존 `alertLeft`(기본 5)는 `five_hour`·`spend_limit` 에만 적용. 키 이름·기본값은 그대로(사용자 `/config` 값 보존).
- 1회 규칙·전달 경로·토스트는 v2.11.0 F1 그대로.

## F2 qhud 0.20.0 — 자동 이어하기 `autoResume`
- userConfig 새 키 `autoResume`(boolean, 기본 true — 사용자 결정 2026-11-16, "Resume work when the usage limit resets"). `alert` 가 false 여도 독립 동작.
- 예약 조건(실제 소진): 메인을 막는 창(`five_hour`·`seven_day`·메인 모델의 주간 창) 중 하나라도 `percentUsed ≥ 100`. `spend_limit` 은 제외.
- 재개 시각: 소진된 창들의 `resetsAt` 중 가장 늦은 값 + 60초. 같은 재개 시각에는 한 번만 예약(세션 atom). 소진 창이 늘어 시각이 늦어지면 기존 타이머를 취소하고 다시 건다.
- 메인 모델 판별: `autoResume` 이 켜져 있으면 `model` 설정과 무관하게 `$.session.model()` 로 모델 id 를 읽어 메인 모델의 주간 창을 고른다(`plan.ts` `scopeName` 재사용). 자동 결정 2026-11-16.
- 방어(검토 r2, 2026-11-16): 재개 시각이 지금 이하(지난 `resetsAt`)이거나 지금+8일 초과면 예약하지 않는다. 취소 때 기억한 시각도 비운다. 타이머가 없으면(autoResume 끔·리로드) 같은 시각이라도 다시 예약할 수 있다 — 단 사용자 프롬프트로 취소된 시각은 다시 걸지 않는다(직접 재개로 본다). 판정 기억은 `await` 전에 동기로 갱신(동시 refresh 토스트 2회 방지).
- 실행: `$.clock.after` 가 울리면 `$.prompt.submit` 으로 고정 영문 문구 1회 — `[qhud] Usage limit has reset. Resume the previous task from where it stopped; read docs/mem.md first if it exists.` (엔진이 세션 idle 때 턴으로 실행).
- 취소: 예약 뒤 qhud 자신이 낸 것이 아닌 프롬프트(`prompt.submit`, origin 없음 포함)가 오면 예약 취소(직접 재개함). `autoResume` 이 꺼지면 취소.
- 메인 알림 덧붙임: `autoResume` 이 켜져 있으면 v2.11.0 알림 문구 끝에 `Auto-resume is on: if the limit runs out, this session resumes automatically after it resets (<시각>); leave notes so the next turn can continue.` 를 붙인다. 시각은 해당 창의 `resetsAt`.
- 사용자: 예약을 걸 때 토스트 1회 `Auto-resume scheduled at <시각>`.
- 제약(README 에 명시): 기본 켜짐이므로 끄는 법(`/config` → `autoResume`)을 README·CHANGELOG 에 분명히 적는다. Claude Code 프로세스가 재개 시각까지 켜져 있어야 함. 권한 우회 모드면 사람 없이 진행됨.
- 로직(소진 판정·재개 시각 계산·문구)은 순수 모듈(`hooks/alert.ts` 확장 또는 `hooks/resume.ts`), `register.tsx` 는 타이머·submit 연결만.
- 테스트: 문턱 분리(주간 2.0/2.1 left, 5h 5 left), `alertLeftWeekly` 범위 밖 → 2, 소진 판정(99.9 vs 100), 여러 창 소진 시 가장 늦은 리셋, 같은 시각 재예약 없음, autoResume on/off 에 따른 알림 덧붙임 유무.
