# v2.11.0 명세 — 사용 한도 임박 알림 (qhud)

배경: 5시간·주간·모델별 주간(fable 등) 한도가 거의 찼을 때 작업 중인 Claude(메인)가 알고 마무리할 수 있게 한다. 사용자 결정(2026-11-16): 남은 양 5% 이하일 때, 메인에게만, 나머지는 권장안(창·리셋당 1회, 다음 도구 호출 때 context 로 전달, 사용자 토스트 함께, userConfig 로 켜고 끄기·문턱 조절).

## F1 qhud 0.19.0 — 한도 임박 알림
- 대상 창: qhud 가 이미 모으는 한도 전부 — `session.usage`/`session.measure` 의 `rateLimits`(`five_hour`·`seven_day`·`spend_limit`) + `plan` 옵션이 켜졌을 때 사용량 엔드포인트의 모델별 주간 창. 엔드포인트를 더 자주 부르지 않는다(`PLAN_EVERY_MS` 유지).
- 조건: 남은 양 `100 − percentUsed` 가 `alertLeft` 이하(기본 5 → 사용 95% 이상).
- 1회 규칙: 같은 창(kind)·같은 리셋(`resetsAt`)에는 한 번만. `resetsAt` 이 바뀌면(새 창) 다시 알릴 수 있다. 세션 상태(atom)로 기억 — 세션을 넘겨 저장하지 않는다.
- 전달(메인만): 조건이 처음 맞으면 알림을 대기열에 둔다. 메인 스레드(`agentId` 없음)의 다음 `tool.call` 결과에 `context` 로 붙이거나, 그보다 먼저 사용자 프롬프트가 오면 `prompt.submit` 의 `context` 로 붙인다. 붙인 뒤 비운다. 서브에이전트의 도구 호출에는 붙이지 않는다. 여러 창이 대기 중이면 한 문구로 묶는다.
- 모델 문구(영문, 한 줄 꼴): `[qhud] Usage limit nearly reached: <창 이름> <used>% used, <left>% left (resets <시각>). Finish the current step, save progress notes, and avoid starting large new work.` 창 이름은 상태 줄 표기와 같게.
- 사용자: 조건이 처음 맞는 순간 `$.ui.toast` 로 같은 내용(짧게)을 한 번 띄운다.
- userConfig 새 키: `alert`(boolean, 기본 true, "Usage limit alert") · `alertLeft`(number, 기본 5, 남은 % 문턱, 1~50 밖이면 5 로 본다). `alert` false 면 대기·토스트·context 모두 없음.
- 로직(조건·1회 판정·문구)은 순수 모듈 `hooks/alert.ts`, `register.tsx` 는 연결만.
- 테스트: 순수 모듈 — 문턱 경계(4.9/5/5.1 left), 같은 리셋 재알림 없음, `resetsAt` 바뀌면 재알림, 여러 창 묶음, `alertLeft` 범위 밖 → 5. 가능하면 가짜 호스트로 메인 `tool.call` 에는 context 가 붙고 서브(`agentId`)에는 안 붙는 것.
