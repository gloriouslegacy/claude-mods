# v1.4.0 기능명세

결정: 2026-10-19 사용자 인터뷰(기본값 true · 세션 시작 1회 · headless 한 줄 안내). 묶음 v1.4.0 (minor).

## F1. agent-flow pane 자동 열기 (`autoOpen`)
- `userConfig` 에 boolean `autoOpen` 을 더한다. 기본값 `true`. title `Open pane on session start`.
- `true` 면 `session.start` 에서 `/aflow` 와 같은 pane(id `agent-flow`)을 `$.ui.open` 으로 연다. `false` 면 지금처럼 `/aflow` 로만 열린다.
- 1회: 한 프로세스(Claude Code 실행)에서 처음 오는 `session.start` 에서만 연다. resume·compact·clear 로 `session.start` 가 다시 와도 열지 않는다 — 사용자가 닫은 pane 을 되살리지 않는다. 이미 `$.ui.panes()` 에 있으면 열지 않는다.
- `isPlaced` 가 false(headless·pane 을 못 띄우는 화면)면 한 줄 안내를 한 번 낸다: pane 을 열 수 없으니 `/aflow text` 를 쓰라는 영문 문구. 안내 수단은 호스트가 제공하는 것(토스트·알림 등) 중 하나, 없으면 open issue 로 보고하고 조용히 넘긴다.
- 2초 틱 조건(pane 이 열려 앞에 보일 때만)·실행 기록·`/aflow` 명령 동작은 바뀌지 않는다.
- 버전: agent-flow 0.5.0 → 0.6.0 (`plugin.json` 과 `.claude-plugin/marketplace.json` 함께).
- 영향: `agent-flow/hooks/register.tsx`, `agent-flow/.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, 필요하면 순수 판정 함수(`hooks/flow.ts`)와 테스트. 다른 플러그인은 건드리지 않는다.
- 예외: `$.ui.open` 이 실패(throw)하면 세션 시작을 막지 않고 삼킨다(`next` 는 항상 호출). `$.ui.panes` 가 없으면 중복 검사 없이 1회 규칙만 쓴다.
- 전제: `session.start` 는 resume·compact 뒤에도 다시 온다(조사 결과, startup/resume 구분 필드 없음). 1회 판정은 register 범위 변수로 한다 — 실측에서 compact 뒤 다시 열리면 open issue.
- 완료: `claude plugin test ./agent-flow` 통과, `bash scripts/check.sh --no-test` 통과, `autoOpen` false 에서 `session.start` 가 `$.ui.open` 을 부르지 않음(테스트 가능하면 순수 함수로).
