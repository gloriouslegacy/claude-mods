# v1.3.0 기능명세

결정: 2026-10-17 사용자 "권장대로". 묶음 v1.3.0 (minor).

## F1. 옛 `/agent-flow` 명령 제거
- `agent-flow` 이름의 명령 등록·`command.run`·`command.describe` 핸들러, 안내 상수 `RENAMED`, 옛 이름 테스트를 지운다.
- `/aflow`·`/aflow text`·`/aflow stats` 동작과 pane id `agent-flow` 는 그대로다.
- agent-flow 0.4.0 → 0.5.0 (`agent-flow/.claude-plugin/plugin.json` 과 `.claude-plugin/marketplace.json` 함께).
- 완료: `claude plugin test ./agent-flow` 통과, 저장소 코드에 `/agent-flow` 명령 등록이 남지 않음.

## F2. 설치기 분할 (진입 파일 + lib)
- 파일: `scripts/install.sh` + `scripts/install-lib.sh`, `scripts/install.ps1` + `scripts/install-lib.ps1`. 릴리스 zip 에서는 네 파일 모두 `my-mods/` 루트.
- 진입 파일이 맡는 것: 인자·도움말, 플랫폼·Claude 버전 확인, 설치 폴더 결정·가드, 번들 확보(옆 번들 / `--zip` / 다운로드 + 체크섬 / 압축 풀기), lib 를 찾아 불러온 뒤 lib 의 모드 함수 호출. 진입 파일만으로 `curl | sh`·`irm | iex` 단독 실행이 가능해야 한다.
- lib 가 맡는 것: current/previous 교체·복구, marketplace 등록, 플러그인 설치·update, 롤백, 제거, 완료 안내.
- lib 찾는 순서: (install 모드면) 확보한 번들 루트 → 진입 파일 옆 → `<설치폴더>/current` → `<설치폴더>/previous`. 없으면 찾은 경로들을 보여 주고 중단한다. sh 는 `.` 로, ps1 은 dot-source 로 불러온다.
- lib 첫머리 주석에 진입 파일이 넘겨주는 변수·함수 목록을 적는다.
- 옵션·출력·동작(가드, `--keep-data`, marketplace 재등록, dry-run)은 바뀌지 않는다. 두 설치기는 같은 동작을 유지한다.
- ps1: 파일 없이 실행되어 `$PSScriptRoot` 가 비면 현재 폴더를 번들로 보지 않는다.
- 크기: 네 파일 모두 400줄 이하 목표, 500줄 미만 필수.

## F3. CI·릴리스 반영
- `release.yml`: 네 파일을 zip 루트로 복사하고, 하나라도 없으면 경고가 아니라 실패. 실행 권한은 `install.sh` 만.
- `ci.yml` `scripts` 잡: shellcheck·PSScriptAnalyzer 대상에 lib 두 개를 더한다. dry-run 명령은 그대로.

## F4. 설치 기본 위치 이동
- 기본값: `${CLAUDE_CONFIG_DIR:-~/.claude}/claude-mods` (sh·ps1 같음). Windows `~` 는 `$HOME`(사용자 프로필). `XDG_DATA_HOME`·`LOCALAPPDATA` 기본값은 없앤다.
- `--dir` 가드에 설정 폴더 자체(`CLAUDE_CONFIG_DIR` 또는 `~/.claude`) 거부를 더한다.
- 옛 위치를 감지·삭제하는 코드는 넣지 않는다. 경로가 바뀌면 기존처럼 같은 이름으로 `marketplace add` 만 다시 한다(플러그인·`/config` 유지).
