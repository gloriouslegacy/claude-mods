# v2.1.0 기능명세

결정: 2026-11-03 사용자 인터뷰(작업 중 입력 자동 기록 모드 — 권장안 채택하되 기본값 켬, 기록 클릭 시 해당 턴으로 이동 요청, 최근 턴 복귀는 엔진 기본 `Jump to bottom (ctrl+End)` 로 충분해 제외). 기존 `/pin` 문법·전달 동작은 바꾸지 않는다. pinboard 0.3.0 → 0.4.0(화면·`userConfig` 추가 → minor), 묶음 v2.1.0.

근거(호스트 2.1.317 타입): `prompt.submit` 입력의 `origin.kind === 'composer'`(사용자 Enter), `command`(슬래시 명령), `isMeta`, `turnId`(턴 도중 입력이면 있음, 대기 중 입력·플러그인 제출이면 없음).

## F1. 자동 기록 대상
- `prompt.submit` 에서 `origin.kind === 'composer'` 이고 `command` 없음, `isMeta` 없음, `turnId` 있음(턴 도중 Enter)인 프롬프트만 기록한다. 대기 중 입력·`/pin` 등 명령·알림·피어·플러그인 제출은 기록하지 않는다. 서브에이전트 턴은 기존처럼 무시.
- 프롬프트는 손대지 않는다: `next(e)` 그대로 통과(텍스트 변경·drop·재제출 금지, 첨부·`wait` 보존). 기록은 부수 효과일 뿐이고 Claude 에게 다시 전달하지 않는다.

## F2. 보존 — 세션 한정
- 기록은 세션 상태 atom(새 키, `types/index.d.ts` 에 선언)에만 둔다. `$.store` `pins:<folder>` 에는 쓰지 않는다 → 세션이 끝나면 저절로 사라지고 정리 코드가 없다. 수동 핀 저장 방식은 그대로.
- 세션당 최근 20개까지(가정 — 넘으면 오래된 것부터 버림).

## F3. 설정
- `userConfig` `capture`(boolean, 기본 `true` — 사용자 결정). 업데이트 후 바로 기록 줄이 생기므로 CHANGELOG·README 에 끄는 방법(`pinboard.capture`)을 적는다. 끄면 기록하지 않고 보드에도 기록 줄을 그리지 않는다.

## F4. 표시
- 같은 보드에 섞어 그리되 흐린 색 + `»` 머리표, 수동 핀과 번호를 공유하지 않는다. 여러 줄·긴 텍스트는 첫 줄만 한 줄로 잘라 그린다.
- 기록 줄의 버튼은 `[×]`(삭제)만. `/pin done/undo/rm N`·`/pin clear` 는 수동 핀에만 적용(변경 없음). `/pin` 접기는 기록 줄도 함께 접는다.
- 문서: `HELP`·`README.md`·`README.ko.md`·`pinboard/CLAUDE.md`·CHANGELOG `## v2.1.0`·`VERSION`.

## F5. 기록 클릭 → 해당 턴으로 이동 (확정 — 사용자 결정 2026-11-03, S1 성공 후 v2.1.0 에 포함)
- 기록할 때 `$.ui.place({ id })` 로 대화 끝에 표식 줄을 놓고 돌려받은 `requestId` 를 기록 항목에 둔다(세션 atom 만). 표식 줄은 pinboard 의 `Placed` 렌더에서 흐린 한 줄 `» #N` 만 그린다(입력 내용은 그리지 않음).
- 보드의 기록 줄 글자를 누르면 `$.ui.scroll({ to: { requestId }, block: 'start' })`. `[×]` 는 그대로.
- 표식이 없거나(`requestId` 없음, compaction 으로 사라짐) scroll 이 `deny` 면 토스트 `That turn is no longer in view (before the last compaction)` 류로 알리고 기록은 지우지 않는다.
- 함께: 정리 후 첫 줄이 빈 문자열이면 기록하지 않는다(r2 리뷰 낮음 결함).
- 안: 기록할 때 `$.ui.place({ id })` 로 대화 끝에 흐린 표식 줄(`» captured`)을 놓고, 보드의 기록 줄 클릭 시 `$.ui.scroll({ to: { requestId: id }, block: 'start' })`. 타입 문서상 사용자 입력에 응답하는 호출이면 대화 줄도 스크롤된다.
- 한계(확인 필요): 표식은 입력 시점 위치라 실제 사용자 메시지(다음 단계에 들어감)보다 약간 앞에 놓인다 · 터미널 스크롤백 모드에서도 이동하는지 · `--resume` 은 표식을 복원하지 않음(F2 와 일치하므로 문제 아님).

## F6. 최근 턴으로 돌아가기 — 제외
- 엔진이 이미 `Jump to bottom (ctrl+End) ↓` 를 띄워 주므로 만들지 않는다(사용자 결정 2026-11-03).

## S1. 이동 실험
- 작은 실험용 mod 로 보드 클릭 → 대화 속 표식 줄까지 스크롤되는지 사용자가 직접 클릭해 확인한다(스크롤백 모드 여부, 표식 위치 어긋남 정도). 결과를 이 절에 적고 F5 를 확정한다.
- 결과(2026-11-03, claude 2.1.317): 표식 2개 모두 band Button onPress 의 `$.ui.scroll` 이 `deny` 없이 성공, 사용자가 화면에서 실제 이동 확인. 버튼 클릭은 사용자 입력으로 인정된다.
