# v2.5.2 명세 — /clear 뒤 상태 복구, agent-flow 정리

## 실측 (2026-11-08, Claude Code 2.1.319, scratchpad probe 플러그인 + tmux)
- `/clear` 때 `session.end`(`e.reason === 'clear'`)는 오고 **`session.start` 는 오지 않는다**(엔진 타입 주석과 일치).
- `/clear` 직후(end 훅이 끝난 뒤 1초 안) **모든 atom 이 선언 초기값으로 돌아간다**.
- 모듈 변수, `$.clock.every` 타이머, 타이머가 잡은 `$` 는 그대로 살아 있다. 그 `$` 로 `read`·`update`·`$.fs` 가 되고 초기화된 새 상태를 본다.
- 코드 주석 "resume, compact and clear send session.start again" 중 clear 는 틀렸다.

## F1. pinboard /clear 복구 (pinboard 0.6.1)
- `/clear` 뒤에도 보드는 `/clear` 전과 같은 핀 목록(`$.store` 의 `pins:<cwd>`)과 같은 접힘 상태를 보인다.
- `/clear` 뒤 새 `/pin`(및 done/rm/undo/clear)은 `pins:<cwd>` 에 저장된다. `pins:`(빈 폴더 키)에 쓰지 않는다.
- 방법은 구현 재량(예: 접힘·폴더를 모듈 변수로도 들고, `session.end` reason clear 뒤 atom 초기화를 확인한 다음 복구; 저장 경로는 폴더가 비면 다시 구함). 복구가 실패해도 세션을 막지 않는다.
- 테스트: 복구 판단을 순수 함수로 두고 단위 테스트(초기화된 상태 + 기억한 값 → 복구할 값). 빈 폴더 키로 저장하지 않는 경로 테스트.

## F2. agent-flow /clear 뒤 띠 Show/Hide 유지 (agent-flow 0.8.2)
